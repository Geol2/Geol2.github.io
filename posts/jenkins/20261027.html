앞 글이 Job 세 개의 전체 구성을 훑은 것이라면, 이 글은 그중 화면 E2E Job 하나를 개발서버 대상으로 잡은 실제 설정이다. 같은 Playwright 테스트를 로컬이 아닌 개발서버에 물려서 돌린 기록이다.

Git, E2E 전용 저장소, Credentials, 브랜치. 테스트 코드를 앱 저장소에서 빼놓으면 테스트만 고쳤을 때 앱 빌드가 따라 돌지 않고, 폴링 주기도 테스트 쪽 사정에 맞춰 짧게 가져갈 수 있다.

둘을 같이 걸어둔 이유가 있다. 폴링만 걸면 테스트 코드를 안 건드린 날은 한 번도 돌지 않는다. 그런데 깨지는 원인은 보통 테스트가 아니라 앱 쪽이 바뀌어서다. 그래서 아무 커밋이 없어도 하루 한 번은 돌도록 정기 실행을 같이 걸었다.

반대로 정기 실행만 두면 테스트를 고쳐 올리고 결과를 보려고 다음 날까지 기다려야 한다. 폴링이 그걸 메운다.

H 는 Jenkins 가 부하를 분산하려고 시각을 알아서 흩뿌리라는 표시다. H 12 는 12시 정각이 아니라 12시대 안의 어느 분으로 잡힌다. 설정 화면 아래에 다음 실행 시각이 찍히니 거기서 확인하면 된다.

빌드 환경

Node 는 Provide Node & npm bin/ folder to PATH 를 켜고 NodeJS Installation 에서 버전을 고른다. 버전을 고정해두면 로컬에서 되던 게 서버에서만 깨지는 경우가 줄어든다.

Credentials 바인딩은 두 개를 걸었다.

종류변수들어가는 것
Secret textAPP_PW테스트 계정 비밀번호
Secret fileAPP_DATASOURCEdatasource.properties 파일 통째

Secret file 이 앞 글에 없던 것이다. 비밀번호 한 줄이 아니라 접속 정보 파일 전체가 필요할 때 쓴다.

주의할 점은 변수에 담기는 값이 파일 내용이 아니라 파일 경로라는 것이다. Jenkins 가 빌드할 때 임시 파일을 하나 떨궈주고 그 경로를 변수에 넣어준다. 그래서 스크립트에서는 변수를 그대로 쓰는 게 아니라 그 경로의 파일을 읽어서 쓴다. 빌드가 끝나면 Jenkins 가 임시 파일을 지운다.

Build Steps

Execute shell

npm ci
npx playwright install chromium
npx playwright test --project=dev --workers=1

--project 가 이 Job 의 핵심이다. playwright.config 에 환경별로 project 를 만들어두면 테스트 코드는 하나로 두고 대상 서버만 갈아끼울 수 있다. 로컬용 project 와 개발서버용 project 를 따로 두고, Job 마다 다른 project 를 지정하는 식이다. 테스트를 환경별로 복사해두지 않아도 된다.

--workers=1 은 병렬 실행을 끈다. 테스트 계정 하나로 동시에 여러 개가 로그인하면 세션이 서로를 밀어내서, 코드는 멀쩡한데 엉뚱한 곳에서 깨진다.

npm ci 는 package-lock.json 에 적힌 그대로 설치한다. npm install 과 달리 lock 파일을 고치지 않아서 빌드할 때마다 같은 버전이 깔린다.

Test output retention 은 None 으로 뒀다. 실패했을 때 원인은 아카이브된 playwright-report 를 열어보면 되므로, Jenkins 쪽에 테스트 출력을 또 쌓아둘 필요가 없다.

JUnit XML 을 내보내려면 playwright.config 의 reporter 에 junit 을 추가하고 출력 파일명을 여기 적은 것과 맞춰야 한다. 이름이 어긋나면 빌드는 성공인데 테스트 결과 그래프만 비어 있게 된다.
