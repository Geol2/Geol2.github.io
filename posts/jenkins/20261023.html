레거시 eGovFrame(Spring MVC + MyBatis + JSP) 프로젝트의 개발서버를 Jenkins로 자동 확인하도록 구성한 기록이다. Jenkins는 내 PC의 Docker 컨테이너로 띄웠고, Windows 에이전트를 하나 붙였다.

무엇을 확인하나

개발서버 확인을 세 갈래로 나눴다. 각각 확인하는 대상이 다르다.

헷갈렸던 점: Jenkins는 개발서버에서 돌지 않는다. Git에서 받는 것도 "어떤 요청을 보내고 무엇을 확인할지"가 적힌 시나리오뿐이다. 실행은 Jenkins가 하고, 개발서버는 이미 떠 있는 애플리케이션으로 요청에 응답만 한다.

[GitHub / SVN] ── 시나리오·코드 ──▶ [내 PC Jenkins (Docker / Windows 에이전트)]
                                         │  HTTP 요청, DB 연결
                                         ▼
                                    [개발서버 WAS + DB]  ← 아무것도 설치하지 않음

Jenkins 기본 용어

  • Job(Item) : 작업 하나. 메인 화면 → Job 클릭 → 왼쪽 Configure(구성)가 Job 설정 화면이다.
  • Jenkins 관리 : 전체 설정. 플러그인 설치(Plugins), 도구 설치(Tools), 비밀번호 보관(Credentials)은 여기서 한다.
  • Job 설정 화면은 위에서부터 General → 소스 코드 관리 → 빌드 유발 → 빌드 환경 → Build Steps → 빌드 후 조치 순서다.

1. API 스모크 (newman)

  1. Jenkins 관리 → Plugins → NodeJS 설치
  2. Jenkins 관리 → Tools → NodeJS installations → 버전 선택, Global npm packages 에 newman
  3. Jenkins 관리 → Credentials → Secret text 로 테스트 계정 비밀번호 등록
  4. Job(Freestyle) 설정
    • 소스 코드 관리 : 시나리오가 있는 Git 저장소
    • 빌드 유발 : Build periodically H/10 8-21 * * 1-5 (평일 08~21시 10분마다)
    • 빌드 환경 : Provide Node & npm bin/ folder to PATH, Use secret text(s) → 변수 APP_PW
    • 빌드 후 조치 : Publish JUnit test result report → results.xml
newman run postman/smoke.postman_collection.json \
  -e postman/dev.postman_environment.json \
  --env-var "password=$APP_PW" \
  --timeout-request 10000 \
  -r cli,junit --reporter-junit-export results.xml

컬렉션에는 조회 API만 넣었다. 10분마다 등록·삭제 API를 돌리면 개발 DB에 테스트 데이터가 계속 쌓인다. 인증 실패(헤더 누락, 미등록 사용자)가 제대로 거부되는지도 같이 넣었다.

2. 화면 E2E (Playwright)

로컬에서 쓰던 Playwright 테스트에 개발서버 대상(project)을 하나 추가했다. 로컬은 설치된 Chrome, Jenkins(Linux 컨테이너)는 Playwright 내장 Chromium을 쓰도록 나눴다.

// playwright.config.js
reporter: process.env.JENKINS_URL
    ? [["list"], ["junit", { outputFile: "results-e2e.xml" }], ["html", { open: "never" }]]
    : undefined,
use: {
    channel: process.env.JENKINS_URL ? undefined : "chrome",
}

컨테이너에서 브라우저를 띄우려면 OS 라이브러리가 필요하다. 최초 한 번 root로 설치한다. (컨테이너를 새로 만들면 다시 해야 한다)

docker exec -u root <jenkins컨테이너> bash -c "export PATH=<NodeJS 도구 경로>/bin:$PATH && npx -y playwright install-deps chromium"

npm ci
npx playwright install chromium
npx playwright test --project=dev --workers=1
  • 빌드 후 조치 : Publish JUnit test result report → results-e2e.xml (이걸 빼먹으면 Job 화면에 테스트 결과 그래프가 안 뜬다)
  • Archive the artifacts → playwright-report/**, test-results/** : 실패 스크린샷을 Jenkins에서 바로 본다
  • --workers=1 : DB에 시드 데이터를 넣는 테스트들이 같은 계정·같은 데이터를 동시에 건드리면 flaky 가 난다. 하루 1회 Job 이라 속도보다 안정성.

3. JUnit (SVN + Windows 에이전트)

  1. Jenkins 관리 → Plugins → Subversion 설치
  2. Credentials → Username with password 로 SVN 계정 등록
  3. Job 설정
    • 소스 코드 관리 : Subversion, Check-out Strategy "Use 'svn update' as much as possible"
    • 빌드 유발 : Poll SCM H/10 8-21 * * 1-5 → 10분마다 확인하고 커밋이 있을 때만 빌드
    • 빌드 후 조치 : target/surefire-reports/*.xml
chcp 65001 > nul
set MAVEN_OPTS=-Dfile.encoding=UTF-8
call mvn -v
call mvn -B clean test -DskipTests=false -Dsurefire.failIfNoSpecifiedTests=false "-Dtest=*Mock*Test,*SpringTest,..."

pom.xml 에 skipTests=true 가 기본값이라 평소 빌드·배포에는 영향 없이 Jenkins에서만 -DskipTests=false 로 켠다. Spring 테스트는 개발 DB에 붙지만 대부분 @Transactional 로 되돌리고, 직접 지우는 테스트는 @AfterEach 에서 정리한다.

운영 메모

  • 로컬 서버와 개발서버가 같은 DB를 보고 있으면, 로컬 E2E 와 Jenkins 빌드를 같은 시간에 돌리지 않는다.
  • 성능 측정하는 시간대에는 10분 주기 Job 을 Disable 해둔다. 측정치에 섞인다.
  • 배포 후 화면 E2E 가 깨지면 먼저 구분한다. 실제 회귀인가, 화면 변경(예: aria-label 추가)에 따라 테스트를 고칠 일인가.
  • 비밀번호·DB 접속 정보는 저장소가 아니라 Jenkins Credentials(Secret text / Secret file)에 둔다.
